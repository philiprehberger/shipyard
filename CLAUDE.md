## What this repo is

**Shipyard** — an atomic-release deploy CLI as a single Go binary, plus a Next.js docs site at `shipyard.philiprehberger.com`. The CLI takes a YAML config, ships a locally-built artifact to a remote SSH host, lands it in a timestamped release directory, gates the symlink flip on a health check, and rolls back automatically if the first health probe after flip fails.

Inverse webhook-relay shape: the **package is the primary artifact**, the docs site exists so the portfolio surface has something to point at.

## Conventions (load-bearing)

- **No Claude / AI attribution.** No `Co-Authored-By`, no "generated by Claude", no AI mentions in commits, code, comments, README, marketing copy, image metadata. Project-wide.
- **Voice and tone match `~/projects/income-ops/CLAUDE.md` § *Voice and tone*.** Lead with diagnosis. Em-dashes, short declarative, concrete numbers, no hedging filler, no emoji, no exclamation points.
- **"Production-shaped," not "production-grade."** This is portfolio infrastructure. Honest framing.
- **Default to writing no comments.** Only add one when the WHY is non-obvious — a hidden constraint, an invariant. Don't explain WHAT well-named code already shows. Don't leave PR-context comments.
- **No premature abstraction.** Three similar files beats a generic base struct. Trust framework + stdlib guarantees instead of validating inside their boundaries.

## Go-specific addenda

- **Go 1.23+**, pinned in `cli/go.mod` with `toolchain`.
- **No third-party logger** — `log/slog` from stdlib only.
- **No third-party YAML lib beyond `gopkg.in/yaml.v3`.**
- **Cobra for CLI structure** (`github.com/spf13/cobra`). Boring choice, right choice.
- **`golang.org/x/crypto/ssh` + `pkg/sftp`** for transport. Don't shell out to `ssh` / `scp` — mature Go SSH client + Windows builds matter.
- **No `context` shortcuts.** Every long-running operation accepts a `context.Context`. Ctrl-C cancels mid-deploy cleanly (releases lock, leaves partial release dir for postmortem).
- **Errors wrap, not flatten.** `fmt.Errorf("uploading artifact: %w", err)` so deploy logs surface the full chain.
- **No global state.** Tests parallel-safe.
- **`go test -race ./...`** in CI. SSH transport uses goroutines for stdout/stderr streaming — races there would be subtle.
- **golangci-lint** with default presets minus `lll`.
- **No build tags except where strictly necessary.** Symlink semantics differ on Windows; that's the one unavoidable place.

## Build + run

```bash
# From repo root
cd cli && go build -o /tmp/shipyard ./cmd/shipyard
/tmp/shipyard version

# Tests
cd cli && go test ./...
cd cli && go test -race ./...

# Lint
cd cli && golangci-lint run

# Docs site
cd web && npm install && npm run dev   # localhost:3006
```

## Deploy

The CLI deploys itself once v0.0.1 ships. Until then, the docs site uses the legacy rsync flow cloned from `~/projects/philiprehberger-nextjs/.scripts/deploy.js`.

After Phase 10:

```bash
shipyard deploy shipyard.yaml          # ships ./web/.next/standalone to /var/www/shipyard-web/
```
